# Project Chemistry

Dating that leads somewhere. Project Chemistry is a Next.js app for adult users to discover profiles, like/pass, match, message, maintain profile preferences, and save date ideas.

## Stack

- Next.js 13 App Router, React, TypeScript, Tailwind CSS
- Auth.js (NextAuth.js) for Google OAuth, email/password sign-in, and JWT sessions
- MongoDB Atlas with Prisma ORM for server-side document data access
- Sonner for UI feedback

The browser never connects directly to MongoDB. Authenticated requests go through Next.js route handlers, which derive the acting user from the verified Auth.js session.

## Local setup

### 1. Requirements

- Node.js 20+
- A MongoDB Atlas Free cluster (or another MongoDB replica set)
- A Google OAuth client configured in Google Cloud Console

### 2. Create a MongoDB Atlas database

Create a free MongoDB Atlas cluster, add a database user, and allow your development IP address in Network Access. Copy the `mongodb+srv://` connection string from Atlas, replace the placeholders in `.env.local`, and use the `project_chemistry` database name. URL-encode special characters in the username and password. Keep the database credentials private.

### 3. Configure environment variables

Copy `.env.example` to `.env.local` and fill in your own values:

- `DATABASE_URL`: application database connection string
- `NEXTAUTH_URL`: local or deployed app URL
- `NEXTAUTH_SECRET`: a long, random secret used to sign/encrypt sessions
- `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`: credentials from your Google OAuth client
- `NEXT_PUBLIC_APP_URL`: local or deployed app URL

In Google Cloud Console, add `http://localhost:3000/api/auth/callback/google` as an authorized redirect URI for local development, and `https://YOUR_DOMAIN/api/auth/callback/google` for production. Never commit these values or paste them into issues.

### 4. Install, migrate, and run

```bash
npm install
npx prisma validate
npx prisma generate
npm run db:push
npm run dev
```

Open http://localhost:3000. The first authenticated request creates the matching application user row. The interest catalog is seeded by the server on first interest lookup.

## Deployment

1. Provision a MongoDB Atlas database (the Free cluster is suitable for development/demo use; observe its storage and usage limits).
2. Configure the Google OAuth client with the deployed callback URL `https://YOUR_DOMAIN/api/auth/callback/google`.
3. Add the environment variables from `.env.example` to your hosting provider. Use production credentials, never the local placeholders.
4. Deploy with Node.js 20+ and run `npm install`, `npx prisma generate`, and `npm run db:migrate` as part of the release.
5. Confirm the validation workflow passes, then smoke-test signup, sign-in, onboarding, discovery, mutual likes, messaging, profile edits, preferences, safety actions, and saved date plans.

Do not expose `DATABASE_URL`, `NEXTAUTH_SECRET`, or `GOOGLE_CLIENT_SECRET` as `NEXT_PUBLIC_*` variables.

## Data and safety notes

- Auth.js manages Google OAuth, password verification, and sessions; MongoDB stores user identities, OAuth accounts, password hashes, and dating profile data.
- New user IDs are generated by Prisma and are the IDs used by all dating relations.
- Server routes reject unauthenticated requests and apply ownership checks for profile writes, preferences, likes, passes, matches, conversations, messages, blocks, reports, and saved plans.
- The app is for adults 18+. The signup screen checks date of birth and the server validates it again before storing it.
- Date-planner venue suggestions are curated ideas, not live venue availability or confirmed bookings.
- This repository cannot include your Google OAuth credentials, production database, DNS, hosting account, or deployment secrets. Those must be configured in your own accounts before a production launch.
